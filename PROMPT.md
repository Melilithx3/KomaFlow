# Стартовый промпт для Claude Code

## Как запустить

1. Создай пустую папку `komaflow`, положи в неё `CLAUDE.md` и папку `docs/` из этого архива.
2. (Желательно) положи свой бенчмарк инференса в `reference/bench/`: оттуда берутся locks окружений, версии моделей, адаптеры и обходные решения.
3. Запусти `claude` в корне папки и вставь текст между линиями.

---

Ты строишь проект **komaflow** с нуля по готовой спецификации. Заказчик — клинер манги, он же основной пользователь десктопа; он не будет следить за каждым шагом, поэтому работай автономно и оставляй понятный след.

**Сначала**
1. Полностью прочитай `CLAUDE.md` и все файлы в `docs/` до первой строки кода.
2. Если есть `reference/bench/`, изучи `README.md`, `bench/catalog.py`, `bench/locks/` и адаптеры в `bench/worker/adapters/`: это проверенная на целевом железе основа для сайдкара.
3. Инициализируй git и монорепо (pnpm workspaces) по `docs/00-overview.md`.
4. Составь список задач по `docs/08-roadmap.md`. Ждать одобрения плана не нужно.

**Затем иди по этапам M0 → M1 → M2 → M3** (подробности и Definition of Done в `docs/08-roadmap.md`). Внутри M1 порядок такой: контракт → сервер → веб и генератор PSD → сид-скрипт для демонстрации. Десктоп и сайдкар — этап M2.

**Спайки** (`docs/07-spikes.md`) выполняй тогда, когда они блокируют решение. Всё, что можно проверить на этой машине, проверяй сам. Для остального (Photoshop, Orange Pi, телефон) напиши харнес и пошаговую инструкцию, добавь в `docs/STATUS.md` раздел «Нужно от человека» и продолжай работу над тем, что от результата не зависит.

**Правила**
- Нерушимые решения из `CLAUDE.md` не пересматривай. Остальные неоднозначности решай сам и записывай как ADR в `docs/decisions/`.
- Делай маленькие вертикальные срезы: код + тесты + коммит. Держи `pnpm test` зелёным.
- После каждого этапа обновляй `docs/STATUS.md`: что готово, что в работе, какие решения приняты, что нужно от человека, известные проблемы.
- Не расширяй объём: всё из списка «Не входит в MVP» (`docs/00-overview.md`, раздел 3) не делай, даже если «это быстро».
- Не выдумывай внешние API. Если не уверен в возможностях библиотеки (особенно `ag-psd`, Tauri 2, PaddleOCR-VL), проверь по документации или коду пакета и запиши вывод в ADR или отчёт спайка.
- Когда закончишь этап, коротко сообщи итог: что работает, как запустить, что дальше.

Начинай.
