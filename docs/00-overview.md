# 00. Обзор и архитектура

## 1. Контекст и цель

Команда из трёх человек переводит мангу: **клинер** (заказчик, основной пользователь десктопа), **переводчик**, **тайпер**. Сейчас в работе один проект — «Межвидовые рецензенты», глава выходит раз в неделю.

Как работают сегодня: клинер чистит страницы и отправляет архив в чат; переводчик пишет Word-документ, где на каждый кусок текста отдельный абзац; тайпер вручную сопоставляет документ и архив и оформляет страницы в Photoshop.
Проблемы: текст не привязан к месту на странице, нет статусов, правки живут в переписке.

**Цель komaflow** — объединить три потока в одном сервисе: текст привязан к объектам на странице, статусы видны всем, PSD со слоями клина, пометок и оригинала собирается автоматически, а текст перевода тайпер копирует из веба.

## 2. Целевой процесс

1. Клинер открывает главу (папка raw-страниц) в десктопе. Запускается анализ: layout-модель находит объекты, OCR-модель читает их текст. Клинер правит боксы, типы и порядок чтения.
2. Клинер клинит страницы во внешних инструментах (в MVP редактора клина в десктопе нет), импортирует готовые PNG (и, по желанию, слой пометок для тайпера) и публикует главу на сервер. Публикация возможна и до клина: raw и разметка достаточны, чтобы переводчик начал работу.
3. Переводчик (веб, в том числе телефон) видит страницу с пронумерованными цветными боксами и таблицу «оригинал | перевод». Работа — заполнить перевод во всех строках.
4. Страница автоматически становится «готовой к тайпу»: есть clean и ни один объект не в состоянии `empty`.
5. Любой участник нажимает «Скачать PSD»: сервер собирает zip с PSD (слои сверху вниз: Notes, Raw (скрыт по умолчанию), Clean) и `manifest.json`. По умолчанию — только готовые страницы. В диалоге экспорта можно снять галочки с raw, clean и notes; галочка «Текст» показана выключенной и неактивной: текстовых слоёв в MVP нет.
6. Тайпер оформляет страницы в Photoshop (текст копирует из веба по номерам боксов, шрифты и размеры настраивает сам) и отмечает страницу «затайплена».

## 3. Объём

### Входит в MVP
- Сервер, веб-интерфейс, генератор PSD (растровые слои: пометки, raw, клин).
- Десктоп: открытие главы, анализ (layout → кропы → OCR), редактор боксов, импорт клина и пометок, публикация на сервер, загрузка главы с сервера.
- Python-сайдкар с двумя моделями (layout и OCR).

### Не входит в MVP (не делать)
Роли и права, регистрация, реалтайм (используем опрос), глоссарий, ветки комментариев (одно поле `comment`), редактирование картинок и тайпинг в вебе, развороты, редактор клина и LaMa в десктопе, любые бэкенды кроме ROCm и CPU, текстовые слои в PSD (галочка «Текст» в диалоге экспорта показана выключенной и неактивной), уведомления, локализации кроме русской, подтягивание бэкапов на десктоп.

## 4. Архитектура

```
 Десктоп (Windows, Tauri 2)          Сервер (Node; Orange Pi / Windows)         Браузеры
 ┌───────────────────────────┐      ┌─────────────────────────────────┐      ┌─────────────┐
 │ React UI  +  Rust-ядро     │HTTPS │ Fastify API  +  статика веба     │HTTPS │ Web (React) │
 │ локальный workspace        ├─────►│ SQLite (WAL)    blobs на диске   │◄─────┤ ПК / телефон│
 │      ▲ localhost HTTP      │      │ воркер экспорта (PSD → zip)      │      └─────────────┘
 │ Python-сайдкар (PyTorch)   │      └─────────────────────────────────┘
 └───────────────────────────┘
```

- Сервер — единственный источник истины для опубликованных данных. Десктоп работает с локальным workspace и синхронизируется явными командами «Опубликовать» / «Загрузить с сервера».
- Реалтайма нет: веб опрашивает сервер (ETag / 304), 15–30 секунд.
- Сервер не обрабатывает картинки при загрузке (проверяет только заголовки); миниатюры делает десктоп.

## 5. Структура репозитория

```
komaflow/
  CLAUDE.md  README.md
  docs/                    # спецификация, STATUS.md, decisions/ (ADR), spikes/ (отчёты)
  packages/
    contract/              # zod-схемы, типы, OpenAPI, чистые хелперы, фикстуры
    psd/                   # генератор PSD (без Node-only API в ядре)
    page-view/             # (по необходимости) общая логика viewport, палитра типов, hit-testing
  apps/
    server/                # Fastify, SQLite, воркер экспорта, admin CLI
    web/                   # React + Vite
    desktop/               # Tauri 2 (src-tauri/ на Rust, src/ на TS)
  sidecar/                 # Python: komaflow_sidecar (CLI + локальный HTTP-сервис)
  tools/                   # seed-скрипты, харнесы спайков
  deploy/                  # nginx, systemd, NSSM, примеры конфигов
  reference/bench/         # бенчмарк инференса пользователя (если положен)
```

## 6. Стек

| Часть | Решение |
|---|---|
| Менеджер пакетов | pnpm workspaces, Node актуальной LTS, TypeScript strict |
| Схемы и валидация | zod; OpenAPI генерируется из схем |
| Сервер | Fastify 5 + zod type provider; SQLite через `better-sqlite3` или встроенный `node:sqlite` (выбрать по результатам S3, спрятать за тонким слоем БД) |
| Веб | React + Vite + TanStack Query; стили — CSS modules или Tailwind; без тяжёлых UI-китов |
| Десктоп | Tauri 2 (WebView2), фронтенд на том же стеке, что и веб; работа с файлами, хэшами, загрузками и токеном (Windows Credential Manager) — на стороне Rust |
| Сайдкар | Python 3.12, PyTorch ROCm (колёса TheRock), `uv` для окружений, веса safetensors |
| PSD | кандидат `ag-psd` (проверяется спайком S1); запасной путь описан в `docs/04-psd.md` |
| Тесты | vitest; pytest для сайдкара |

## 7. Окружение

- **ПК клинера:** Windows, видеокарта AMD gfx1031 (12 ГБ VRAM). Здесь работают десктоп и сайдкар.
- **Сервер:** Orange Pi Zero 3 (ARM64, 4 ГБ ОЗУ, SD-карта); запасной вариант — Windows-ПК. Белый IP, nginx с пробросом портов, домен `komaflow.tlinmo.site`, HTTPS через certbot.
- **Устройства пользователей:** клинер — ПК (и иногда ноутбук, не приоритет); переводчик — ПК и телефон; тайпер — ПК и ноутбук.
- Рабочая машина разработки может быть любой; всё, что требует специального железа, проверяется по `docs/07-spikes.md`.

## 8. Глоссарий

| Термин | Значение |
|---|---|
| raw | исходная страница (скан) |
| clean / клин | страница с вычищенным текстом (PNG, того же размера, что raw) |
| notes / пометки | прозрачный PNG того же размера: обводка «тяжёлых мест» для тайпера |
| объект | область на странице, подлежащая переводу; тип `bubble`, `sfx`, `onomatopoeia` или `text` (универсальный) |
| бокс | прямоугольник объекта `{x, y, w, h}` в пикселях raw-страницы |
| разметка (markup) | набор объектов страницы с геометрией, типами и порядком — данные десктопа |
| перевод (text data) | `source_text`, `translation`, `state`, `comment`, `flagged` — данные веба |
| blob | файл, адресуемый по SHA-256 |
| sync | публикация десктопом разметки и ссылок на файлы одной главы, одной транзакцией |
| export | асинхронная сборка zip с PSD для главы |
| готова к тайпу | есть clean и нет объектов в состоянии `empty` |
