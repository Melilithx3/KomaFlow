# Диагностика на ПК клинера

Если анализ, OCR или автоклин не работают, соберите отчёты ниже и пришлите их. Это проверка на ошибки, а не замер скорости.

## 1. Обновить код
```powershell
cd D:\komaflow
git pull
pnpm install
cd sidecar
.venv\Scripts\python -m pip install -e .
```

## 2. Проверка движка и моделей (главное)
```powershell
.venv\Scripts\komaflow-sidecar doctor
```
Что делает: проверяет пути и окружения, видеокарту и установленные модели. Затем запускает каждую модель (разметка, OCR, LaMa) на искусственной странице дважды: «холодный» и «прогретый» запуск. В конце проверяет, что неактивные модели переносятся в ОЗУ.
- Каждый шаг ограничен по времени. Если модель зависла, будет `[FAIL]` с хвостом её лога, а не бесконечное ожидание. Срок загрузки модели меняется параметром `--load-timeout 1800` (в секундах).
- Отчёт печатается на экран и сохраняется в `%LOCALAPPDATA%\komaflow\sidecar\logs\doctor-<дата>.txt`. **Пришлите этот файл.**
- Если зависла уже вторая часть («GPU and models»), значит, не импортируется сам torch в окружении: пришлите отчёт как есть.

## 3. Автотесты (по желанию)
```powershell
cd D:\komaflow
pnpm test
cd sidecar
.venv\Scripts\python -m pytest
```
Если что-то красное, пришлите вывод целиком.

## 4. Собранное приложение
После `pnpm --filter @komaflow/desktop tauri build` и установки:
- На стартовом экране, в блоке «Движок анализа», указано состояние движка. Если там ошибка, скопируйте её текст.
- В строке статуса редактора выводятся ошибки разметки, OCR и LaMa.
- **Консоль:** в окне программы нажмите `Ctrl+Shift+I` → вкладка Console. Пришлите красные строки (они появятся, например, при открытии вкладки «Клин»).
- **Логи** из папки `%LOCALAPPDATA%\komaflow\sidecar\logs\`: `sidecar.log` и `worker-*.log`.

## 5. Режим `tauri dev`
`pnpm --filter @komaflow/desktop tauri dev`: окно с консолью (`Ctrl+Shift+I`) плюс вывод в терминале. Пришлите ошибки из обоих мест.
