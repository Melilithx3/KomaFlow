# 04. Генератор PSD

## 1. Назначение и интерфейс

Пакет `packages/psd` превращает данные страницы в PSD (RGB, 8 бит). Это чистая функция; ядро **не должно зависеть от Node-only API**, чтобы при необходимости его можно было запустить в браузере (см. §8).

```ts
interface ImageCodec {                       // инжектируется; в Node — sharp или pngjs
  decodePng(bytes: Uint8Array): Promise<{ width: number; height: number; rgba: Uint8Array }>;
}
interface PsdPageInput {
  page: { index: number; width: number; height: number };
  clean?: Uint8Array;                        // PNG; нужен, если layers.clean
  notes?: Uint8Array;                        // PNG с альфой, по желанию
  raw?: Uint8Array;                          // оригинал; нужен, если layers.raw
  objects: Array<{ id: string; order: number; type: ObjectType;
                   box: Box; textBox?: Box | null;
                   translation: string; state: TranslationState }>;
  layers: ExportLayers;                      // какие слои включать
  settings: PsdSettings;
}
type ExportLayers = { raw: boolean; clean: boolean; notes: boolean; text: boolean };
generatePsd(input: PsdPageInput, codec: ImageCodec): Promise<Uint8Array>;
```

Генератор принимает уже отобранные неудалённые объекты по порядку. Текстовые слои создаются только для объектов в состоянии `translated` с непустым переводом.

## 2. Структура слоёв (сверху вниз)

| № | Слой | Содержимое | Включается, если |
|---|---|---|---|
| 1 | `Notes` | пометки клинера, видимый, `notes_opacity` из настроек | `layers.notes` и у страницы есть `notes_hash` |
| 2 | `Raw` | оригинал, **скрыт по умолчанию** (`raw_layer_visible: false`), включается одним кликом для сверки | `layers.raw` |
| 3 | группа `Text` | по текстовому слою на объект, имя `07_bubble` (`{order:02d}_{type}`) | `layers.text` (в MVP всегда `true`) |
| 4 | `Clean` | клин, нижний слой | `layers.clean` |

Слои выбирает пользователь галочками в диалоге экспорта: `raw`, `clean`, `notes` по умолчанию включены. Галочка `text` в MVP **показывается, но неактивна** (всегда включена): это задел на будущее, когда тайперу может понадобиться брать текст из веба без текстовых слоёв в PSD. API уже принимает `layers.text`, но значение `false` в MVP отклоняется (`422`). Должен остаться хотя бы один слой (в MVP это гарантирует `text`). Если снят `clean`, фон документа прозрачный.

Композитное изображение документа строится из видимых растровых слоёв (чтобы превью в проводнике и просмотрщиках не было пустым). Проверить в S1, что Photoshop не жалуется. В ag-psd порядок `children` может идти снизу вверх; сверить по документации.

## 3. Текстовые слои

- **Настоящие, редактируемые** текстовые слои (не растр): инструмент «Текст» в Photoshop открывает их, шрифт и размер меняются.
- Абзацный текст (box text) с рамкой `text_rect`: `text_box`, а если его нет — `box`, сжатый на отступ `text_padding[type]` (доля стороны с каждой стороны; по умолчанию 0,10 для `bubble`, 0 для остальных), обрезанный границами страницы.
- Выравнивание по центру, цвет `text_color`, шрифт `default_font` (PostScript-имя), межстрочный интервал `line_height`.
- `\n` в переводе → разрыв абзаца (в Photoshop `\r`). Начальные и конечные пробелы обрезаются.
- Размер шрифта: `base_font_size[type]` (px), затем простая оценка вписывания:
  ```
  avg_char_w = 0.55 * size;  line_h = size * line_height
  wrap по словам в ширину text_rect.w; если число_строк * line_h > text_rect.h → size -= 1
  повторять до min_font_size
  ```
  Это эвристика, а не гарантия: отображение текста в генераторе и в Photoshop отличается; доводит тайпер. Эвристика — отдельная чистая функция с юнит-тестами.
- Единицы: размеры в настройках заданы в пикселях страницы. Для PSD пересчитываются в пункты: `pt = px * 72 / dpi`. DPI документа берётся из настроек (по умолчанию 72, тогда `pt = px`).

## 3.1 Настройки (`projects.settings_json.psd`, схема `PsdSettings`)

```json
{
  "default_font": "ArialMT",
  "dpi": 72,
  "text_color": "#000000",
  "justification": "center",
  "base_font_size": { "bubble": 28, "sfx": 40, "onomatopoeia": 36, "text": 24 },
  "min_font_size": 10,
  "line_height": 1.15,
  "text_padding": { "bubble": 0.10, "sfx": 0, "onomatopoeia": 0, "text": 0 },
  "raw_layer_visible": false,
  "notes_opacity": 100
}
```
Значения по умолчанию временные: у тайпера пока не выяснены версия Photoshop, любимый шрифт и DPI, их нужно легко менять в UI проекта.

## 4. Экспорт главы

`POST /chapters/{id}/exports` создаёт задание; воркер обрабатывает **одну страницу за раз** и собирает zip потоково (без накопления всего архива в памяти).

**Отбор страниц:** `only_ready = true` (по умолчанию) → только `ready_for_typing`; `false` → все страницы. Если запрошен слой `clean`, страницы без clean пропускаются с причиной `no_clean`. Параметр `page_ids` дополнительно сужает выбор (скачивание одной страницы).

**Содержимое zip:**
```
<chapter_number>/001.psd, 002.psd, …      # имя по idx страницы, 3 цифры
manifest.json
errors.json                                # только если были ошибки
```

**`manifest.json`:**
```json
{
  "format": 1, "export_id": "…", "created_at": "…", "created_by": { "id": "…", "login": "…" },
  "project": { "id": "…", "title": "…" }, "chapter": { "id": "…", "number": "12", "title": null },
  "params": { "only_ready": true, "layers": { "raw": true, "clean": true, "notes": true, "text": true }, "page_ids": null },
  "generator": { "name": "komaflow-psd", "version": "0.1.0" },
  "pages": [{
    "page_id": "…", "idx": 1, "file": "001.psd", "psd_input_hash": "…", "markup_rev": 3,
    "raw_hash": "…", "clean_hash": "…", "notes_hash": null,
    "objects": [{ "id": "…", "order": 1, "type": "bubble", "geometry_ver": 2, "text_ver": 5 }],
    "skipped_objects": [{ "id": "…", "reason": "skipped" }]
  }],
  "skipped_pages": [{ "page_id": "…", "idx": 4, "reason": "not_ready" }]
}
```
`psd_input_hash` считается по `docs/01-data-model.md` §5. Версии пишутся для информации; актуальность определяет хэш.

**Ошибки:** сбой одной страницы не рушит экспорт; она попадает в `errors.json` с кодом (`PSD_TOO_LARGE`, `DECODE_FAILED`, `GENERATION_FAILED`), экспорт завершается как `done` с непустым `errors`, если хотя бы одна страница получилась. Ограничения формата PSD: сторона ≤ 30 000 px, файл ≤ 2 ГБ → понятная ошибка `PSD_TOO_LARGE`.

## 5. Тесты

- Юнит: вписывание текста, `text_rect`, нумерация имён слоёв, пересчёт px → pt, канонический JSON и `psd_input_hash`.
- Golden-тесты: сгенерировать PSD и прочитать обратно (`readPsd`), проверить дерево слоёв, имена, видимость, наличие настоящих текстовых слоёв (`text.text`), содержимое текста.
- Устойчивость: пустая страница без объектов, объект на краю страницы, очень длинный текст, кириллица и спецсимволы, 40+ объектов, страница 2000×3000 (замер времени и памяти).
- Ручная проверка в Photoshop — спайк S1 и повторяется при смене библиотеки.

## 6. Запасной путь, если S1 провален

Если редактируемые текстовые слои надёжно не получаются, генератор выпускает PSD только с растровыми слоями (Raw, Notes, Clean) и кладёт в zip файл `komaflow-text.json` (объекты с рамками и текстом) и скрипт `apply-text.jsx`. Тайпер запускает его в Photoshop («Файл → Сценарии → Обзор»), скрипт создаёт текстовые слои по данным. Спайк S1 должен подтвердить работоспособность этого пути на реальном Photoshop, прежде чем его выбирают. Решение фиксируется в ADR.

## 7. Производительность

Цель: страница 2000×3000 на Orange Pi — не более ~30 с и пик памяти < 300 МБ (замеряется в S1/S3). Декодирование PNG — самая тяжёлая часть; предпочтительно нативный кодек, если он ставится на ARM64.

## 8. Если Orange Pi слишком медленный

Ядро генератора изоморфное, поэтому запасной вариант — собирать PSD в браузере пользователя (клиент скачивает blob'ы, генерирует страницы по одной и пакует zip потоково, например через `fflate`). Сервер при этом отдаёт только данные. Этот вариант не реализуется в MVP, но архитектура его не закрывает: никаких `fs`, `Buffer` и серверных путей в `packages/psd`.
