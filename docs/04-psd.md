# 04. Генератор PSD

> **В MVP PSD не содержит текстовых слоёв.** Слои: пометки, скрытый raw, клин. Текст перевода тайпер берёт из веба (кнопки «Копировать»).
> Галочка «Текст» в диалоге экспорта показана **выключенной и неактивной**: пользователь не может её включить, а API отклоняет `layers.text = true`.
> Дизайн текстовых слоёв сохранён в §3 как задел на будущее. Реализовывать его сейчас не нужно.

## 1. Назначение и интерфейс

Пакет `packages/psd` превращает данные страницы в PSD (RGB, 8 бит). Это чистая функция; ядро **не должно зависеть от Node-only API**, чтобы при необходимости его можно было запустить в браузере (см. §8).

```ts
interface ImageCodec {                       // инжектируется; в Node — sharp или pngjs
  decodePng(bytes: Uint8Array): Promise<{ width: number; height: number; rgba: Uint8Array }>;
}
type ExportLayers = { raw: boolean; clean: boolean; notes: boolean; text: boolean };  // в MVP text всегда false

interface PsdPageInput {
  page: { index: number; width: number; height: number };
  clean?: Uint8Array;                        // PNG; нужен, если layers.clean
  notes?: Uint8Array;                        // PNG с альфой; нужен, если layers.notes
  raw?: Uint8Array;                          // оригинал; нужен, если layers.raw
  layers: ExportLayers;                      // какие слои включать
  settings: PsdSettings;
  objects?: Array<{ id: string; order: number; type: ObjectType;   // только при layers.text (после MVP)
                    box: Box; textBox?: Box | null;
                    translation: string; state: TranslationState }>;
}
generatePsd(input: PsdPageInput, codec: ImageCodec): Promise<Uint8Array>;
```

## 2. Структура слоёв (сверху вниз)

| № | Слой | Содержимое | Включается, если |
|---|---|---|---|
| 1 | `Notes` | пометки клинера (PNG с альфой), видимый, `notes_opacity` из настроек | `layers.notes` и у страницы есть `notes_hash` |
| 2 | `Raw` | оригинал, **скрыт по умолчанию** (`raw_layer_visible: false`), включается одним кликом для сверки | `layers.raw` |
| 3 | группа `Text` | **после MVP.** В MVP этого слоя нет | `layers.text` (в MVP всегда `false`) |
| 4 | `Clean` | клин, нижний слой | `layers.clean` и у страницы есть `clean_hash` |

Правила выбора слоёв:
- Пользователь галочками выбирает `raw`, `clean`, `notes` (по умолчанию все включены). Галочка `text` **выключена и неактивна**.
- API: `text` по умолчанию `false`; `text: true` → `422 VALIDATION_ERROR` («текстовые слои пока не поддерживаются»). Если `raw`, `clean` и `notes` все `false` → `422`.
- Если для страницы не нашлось ни одного из выбранных слоёв (например, выбраны только пометки, а их у страницы нет), страница пропускается с причиной `no_layers`.
- Если слой `Clean` не выбран или отсутствует, фон документа прозрачный.
- Композитное изображение документа строится из видимых растровых слоёв (чтобы превью в проводнике и просмотрщиках не было пустым). Проверить в S1, что Photoshop не жалуется. В ag-psd порядок `children` может идти снизу вверх; сверить по документации.

## 3. Текстовые слои (после MVP — не реализовывать)

Этот раздел описывает будущую функцию: включение галочки «Текст». Он оставлен, чтобы дизайн не пропал, но в MVP никакой код по нему не пишется.

- **Настоящие, редактируемые** текстовые слои (не растр): инструмент «Текст» в Photoshop открывает их, шрифт и размер меняются.
- Слои создаются только для объектов в состоянии `translated` с непустым переводом; имя слоя `07_bubble` (`{order:02d}_{type}`); все они лежат в группе `Text` между `Raw` и `Clean`.
- Абзацный текст (box text) с рамкой `text_rect`: `text_box`, а если его нет — `box`, сжатый на отступ `text_padding[type]` (доля стороны с каждой стороны; по умолчанию 0,10 для `bubble`, 0 для остальных), обрезанный границами страницы.
- Выравнивание по центру, цвет `text_color`, шрифт `default_font` (PostScript-имя), межстрочный интервал `line_height`.
- `\n` в переводе → разрыв абзаца (в Photoshop `\r`). Начальные и конечные пробелы обрезаются.
- Размер шрифта: `base_font_size[type]` (px), затем простая оценка вписывания:
  ```
  avg_char_w = 0.55 * size;  line_h = size * line_height
  wrap по словам в ширину text_rect.w; если число_строк * line_h > text_rect.h → size -= 1
  повторять до min_font_size
  ```
  Это эвристика, а не гарантия: отображение текста в генераторе и в Photoshop отличается; доводит тайпер.
- Единицы: `pt = px * 72 / dpi`.

### 3.1 Настройки (`projects.settings_json.psd`, схема `PsdSettings`)

```json
{
  "default_font": "ArialMT",
  "dpi": 72,
  "text_color": "#000000",
  "justification": "center",
  "base_font_size": { "bubble": 28, "sfx": 40, "onomatopoeia": 36, "text": 24 },
  "min_font_size": 10,
  "line_height": 1.15,
  "text_padding": { "bubble": 0.10, "sfx": 0, "onomatopoeia": 0, "text": 0 },
  "raw_layer_visible": false,
  "notes_opacity": 100
}
```
**В MVP используются только `raw_layer_visible` и `notes_opacity`.** Остальные поля хранятся в БД и проверяются схемой (чтобы не делать миграцию позже), но в интерфейсе скрыты. Значения по умолчанию временные: у тайпера пока не выяснены версия Photoshop, любимый шрифт и DPI.

## 4. Экспорт главы

`POST /chapters/{id}/exports` создаёт задание; воркер обрабатывает **одну страницу за раз** и собирает zip потоково (без накопления всего архива в памяти).

**Отбор страниц:** `only_ready = true` (по умолчанию) → только `ready_for_typing`; `false` → все страницы. Страницы без выбранных слоёв пропускаются с причиной `no_layers`; если запрошен слой `clean`, а его у страницы нет, она пропускается с причиной `no_clean`. Параметр `page_ids` дополнительно сужает выбор (скачивание одной страницы).

**Содержимое zip:**
```
<chapter_number>/001.psd, 002.psd, …      # имя по idx страницы, 3 цифры
manifest.json
errors.json                                # только если были ошибки
```

**`manifest.json`:**
```json
{
  "format": 1, "export_id": "…", "created_at": "…", "created_by": { "id": "…", "login": "…" },
  "project": { "id": "…", "title": "…" }, "chapter": { "id": "…", "number": "12", "title": null },
  "params": { "only_ready": true, "layers": { "raw": true, "clean": true, "notes": true, "text": false }, "page_ids": null },
  "generator": { "name": "komaflow-psd", "version": "0.1.0" },
  "pages": [{
    "page_id": "…", "idx": 1, "file": "001.psd", "psd_input_hash": "…", "markup_rev": 3,
    "raw_hash": "…", "clean_hash": "…", "notes_hash": null
  }],
  "skipped_pages": [{ "page_id": "…", "idx": 4, "reason": "not_ready" }]
}
```
Причины пропуска страниц: `not_ready`, `no_clean`, `no_layers`. `psd_input_hash` считается по `docs/01-data-model.md` §5; `markup_rev` пишется для информации. Когда появятся текстовые слои, в запись страницы добавятся списки объектов с версиями.

**Ошибки:** сбой одной страницы не рушит экспорт; она попадает в `errors.json` с кодом (`PSD_TOO_LARGE`, `DECODE_FAILED`, `GENERATION_FAILED`), экспорт завершается как `done` с непустым `errors`, если хотя бы одна страница получилась. Ограничения формата PSD: сторона ≤ 30 000 px, файл ≤ 2 ГБ → понятная ошибка `PSD_TOO_LARGE`.

## 5. Тесты

- Юнит: выбор слоёв по флагам и наличию файлов, порядок слоёв, имена, канонический JSON и `psd_input_hash`, валидация `layers` (`text: true` → ошибка, ни одного слоя → ошибка).
- Golden-тесты: сгенерировать PSD и прочитать обратно (`readPsd`), проверить дерево слоёв, имена, порядок, видимость (`Raw` скрыт), непрозрачность `Notes`, размеры; проверить, что **текстовых слоёв нет**.
- Устойчивость: все допустимые комбинации галочек, страница без пометок, PNG с частичной прозрачностью, страница 2000×3000 и высокая страница 1600×10000 (замер времени и памяти).
- Ручная проверка в Photoshop — спайк S1 и повторяется при смене библиотеки.

## 6. На будущее: как включить текстовые слои

Когда понадобится галочка «Текст»: выполнить спайк S1b (`docs/07-spikes.md`), реализовать §3 и снять запрет `text: true` в API и UI. Если редактируемые текстовые слои надёжно не получатся, запасной путь: PSD с растровыми слоями плюс `komaflow-text.json` (объекты с рамками и текстом) и скрипт `apply-text.jsx`, который тайпер запускает в Photoshop («Файл → Сценарии → Обзор»), и он создаёт текстовые слои. Работоспособность на реальном Photoshop нужно подтвердить до выбора этого пути.

## 7. Производительность

Цель: страница 2000×3000 на Orange Pi — не более ~30 с и пик памяти < 300 МБ (замеряется в S1/S3). Декодирование PNG и запись слоёв — самая тяжёлая часть; предпочтительно нативный кодек, если он ставится на ARM64.

## 8. Если Orange Pi слишком медленный

Ядро генератора изоморфное, поэтому запасной вариант — собирать PSD в браузере пользователя (клиент скачивает blob'ы, генерирует страницы по одной и пакует zip потоково, например через `fflate`). Сервер при этом отдаёт только данные. Этот вариант не реализуется в MVP, но архитектура его не закрывает: никаких `fs`, `Buffer` и серверных путей в `packages/psd`.
