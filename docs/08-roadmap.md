# 08. Дорожная карта, тесты и протокол работы

## 1. Этапы

### M0. Фундамент
- `git init`, pnpm workspaces, tsconfig base (strict), ESLint + Prettier, vitest, скрипты `dev:server`, `dev:web`, `test`, `build`.
- `packages/contract`: zod-схемы всех DTO из `docs/02-api.md`, формат ошибок, UUID v7, `canonicalJson`, `psd_input_hash`, авто-порядок чтения, геометрические хелперы (клэмп, вхождение в страницу), генератор тестовых фикстур (небольшие PNG-страницы с боксами).
- `docs/STATUS.md`, `docs/decisions/`, `docs/spikes/`, `README.md` с командами.

**DoD:** `pnpm install && pnpm test && pnpm build` проходят на чистом клоне; контрактные тесты зелёные.

### M1. Сервер + веб + PSD (первый полезный срез)
Порядок задач:
1. БД-слой, миграции, `komaflow-admin` (`create-user`, `set-password`, `backup`, `dump-text`, `seed`).
2. Авторизация: login/logout/me/sessions/password, лимит попыток, CSRF-заголовок, ограничение `desktop`-эндпоинтов.
3. Blobs: check/put/get, валидация, лимиты, атомарная запись.
4. Чтение: проекты, главы, страницы, ETag/304, вычисляемые статусы.
5. Sync: транзакция, ревизии разметки, мягкое удаление и восстановление, валидации, идемпотентность.
6. PATCH объектов: конфликты по полям, история, правила `state`, `typed`, `seen`.
7. Экспорт: очередь, воркер, потоковый zip, manifest, `psd_input_hash`, актуальность, очистка по сроку.
8. Сид-скрипт: заливает фикстурную главу **через настоящее API** (имитирует десктоп), для демонстрации и e2e-тестов.
9. Веб: вход, проекты и главы, экран главы, страница (десктоп и мобильный), конфликты, экспорт, настройки, баннер изменений.
10. Генератор PSD: сначала чистая часть (выбор слоёв, manifest, хэши, zip), затем запись растрового PSD по результатам S1. Текстовые слои не делать.

**DoD:** через сид-скрипт создаётся глава; в вебе можно перевести страницы с компьютера и мобильного вьюпорта; конфликт двух вкладок разрешается диалогом; экспорт даёт zip с PSD нужной структуры слоёв (порядок, видимость, галочки raw/clean/notes; галочка «Текст» выключена и неактивна), `manifest.json` и признаком устаревания после замены клина или пометок; все тесты зелёные.

### M2. Десктоп + сайдкар
1. Tauri-оболочка: вход, токен в Credential Manager, клиент API, настройки.
2. Workspace, хранилище состояния, команды с undo/redo, автосохранение и восстановление.
3. Холст: просмотр, pan/zoom, редактор боксов, список объектов и инспектор, авто-порядок, горячие клавиши.
4. Сайдкар: CLI (по итогам S2), затем локальный HTTP-сервис, установка окружения при первом запуске.
5. Интеграция анализа: очередь, прогресс, отмена, `ApplyAnalysis`, «Перечитать OCR».
6. Импорт клина и пометок с таблицей сопоставления.
7. Публикация (хэши, миниатюры, blobs, sync, конфликт) и загрузка с сервера, подтягивание флажков.
8. Установщик (NSIS/MSI).

**DoD:** реальная глава публикуется с ПК клинера и открывается в вебе; публикация переживает обрыв связи; без сайдкара приложение работает вручную; плавность холста подтверждена на странице 2000×3000.

### M3. Эксплуатация
`deploy/` (nginx, systemd, NSSM, таймер бэкапа), инструкции установки и обновления, нагрузочный прогон на трёх клиентов, проход по чеклисту безопасности из `docs/03-server-ops.md`, `gc-blobs`, финальный README оператора.

### После MVP (не делать сейчас)
Автоклин на LaMa, редактор клина (кисть, ластик, магическая кисть), текстовые слои в PSD (галочка «Текст», дизайн в `docs/04-psd.md` §3, спайк S1b), глоссарий, ветки комментариев, бэкап-pull на десктоп, синхронизация клина между устройствами клинера, Intel XPU, уведомления, SSE.

## 2. Зависимости между задачами

```
M0 contract ─┬─► сервер (M1.1–M1.8) ─► веб (M1.9)
             ├─► генератор PSD, чистая часть ─► запись PSD (после S1)
             └─► десктоп (M2) на моке по OpenAPI, затем на реальном сервере
S2 ─► сайдкар (M2.4)      S3 ─► выбор драйверов (до M1.1 желательно, не блокирует)
```

Веб и десктоп можно писать параллельно на моке API, сгенерированном из схем.

## 3. Стратегия тестирования

- **Контракт:** схемы принимают валидные и отвергают невалидные данные; фикстуры используются повсеместно.
- **Сервер (интеграционные, реальный SQLite во временной папке):**
  - sync: идемпотентность, атомарность, восстановление удалённых объектов, `REVISION_CONFLICT`, `BLOBS_MISSING`, `SIZE_MISMATCH`, `RAW_IMMUTABLE`, инварианты порядка и границ;
  - PATCH: правки разных полей сливаются, одного поля даёт `FIELD_CONFLICT`, неизменённое значение не создаёт версию, правила `state`;
  - sync никогда не меняет текст, PATCH никогда не меняет геометрию;
  - авторизация: сессии, отзыв, ограничение `desktop`-эндпоинтов, CSRF-заголовок, лимит попыток;
  - blobs: поток, несовпадение хэша, лимиты, неверный тип;
  - экспорт: отбор страниц, флаги слоёв (`text: true` → 422, ни одного слоя → 422), manifest, `psd_input_hash`, устаревание после замены клина или пометок (но не после правки перевода), очистка по сроку.
- **PSD:** golden-тесты (читаем результат обратно) и сценарии устойчивости из `docs/04-psd.md`.
- **Веб:** компонентные тесты и Playwright (основные сценарии, конфликт, мобильный вьюпорт).
- **Десктоп:** юнит-тесты хранилища и команд (undo/redo, слияние жестов), сопоставления файлов при импорте, авто-порядка; ручной чек-лист плавности холста.
- **Сайдкар:** pytest (контракты, отмена, процессы), GPU-тесты за маркером.
- **Нагрузка:** три клиента на Orange Pi (S3 и M3).

## 4. Протокол работы

- **Коммиты:** conventional commits, маленькие, после зелёных тестов.
- **`docs/STATUS.md`** обновляется после каждого среза. Разделы: «Сделано», «В работе», «Решения (ссылки на ADR)», «Нужно от человека», «Известные проблемы».
- **ADR** (`docs/decisions/NNNN-title.md`, до 15 строк): контекст, решение, последствия. Пишутся для каждого выбора, который не зафиксирован в спецификации.
- **Вопросы человеку** — только если решение необратимо дорогое или противоречит нерушимым пунктам `CLAUDE.md`. Иначе решай, фиксируй в ADR и иди дальше.
- **Что нельзя проверить без железа** — харнес + инструкция + запись в «Нужно от человека»; работа идёт дальше.
- **Не расширять объём:** всё из списка «Не входит в MVP» (`docs/00-overview.md` §3) и «После MVP» не делать.
- **Тестовые данные:** страницы манги и результаты не коммитятся; для тестов используются синтетические фикстуры.
