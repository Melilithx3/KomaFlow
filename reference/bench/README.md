# Бенчмарк инференса: koharu-layout / PaddleOCR-VL-1.6 / lama-manga на AMD gfx1031 (Windows)

Автоматически проверяет, **какие способы инференса реально работают** на RX 6700 XT / 6750 XT
(RDNA2, gfx1031) под Windows, насколько они быстрые и сколько ресурсов потребляют.

## Запуск на другом ПК (то же железо)

1. На этом ПК соберите архив:
   ```
   py make_portable.py                  # только код, ~0.1 МБ — модели и окружения скачаются на месте
   py make_portable.py --with-models    # + веса моделей (~2.2 ГБ), чтобы не качать их повторно
   py make_portable.py --with-test-data # + ваши страницы из test_data/
   ```
   Архив появится в `dist/`. Флаги можно совмещать.
2. На другом ПК: распакуйте в любую папку с ~20 ГБ свободного места (не в `Program Files`),
   положите страницы в `test_data\` и запустите **`start.bat`** (двойным кликом или из консоли,
   например `start.bat --gpu-only`). Нужен только Python ≥ 3.10 для запуска — сам бенчмарк
   ставит всё остальное в свою папку. Права администратора не нужны.

**Те же тесты, те же версии.** `bench/locks/<окружение>.txt` хранит точные версии Python (3.12.16)
и всех пакетов окружений, проверенных на RX 6750 XT. При установке они применяются как
ограничения, поэтому на втором ПК ставится ровно тот же набор (включая torch 2.14.0+rocm10.1.0
и пакеты ROCm 10.1.0). Модели закреплены по commit hash в `bench/catalog.py`.
Окружения `.envs/` между ПК не копируются: venv привязан к абсолютным путям.
Если на втором ПК окажется другая видеокарта, тесты всё равно пройдут, но в логе и отчёте
появится предупреждение, что результаты несопоставимы.

## Быстрый старт

1. Положите страницы манги (PNG / JPG / WebP) в `test_data/`.
2. Запустите `start.bat` (или `py run_all.py`; нужен любой установленный Python ≥ 3.10).
3. Дождитесь окончания (первый запуск скачивает ~12 ГБ окружений и ~2.3 ГБ моделей).
4. Откройте `runs/<дата_время>/summary.html`.

Ничего выбирать не нужно — все комбинации из `bench/catalog.py` проверяются по очереди.

### Полезные опции
| Опция | Что делает |
|---|---|
| `--list` | показать все комбинации и выйти |
| `--gpu-only` / `--cpu-only` | только GPU-комбинации (ROCm, DirectML) / только CPU |
| `--resume last` | продолжить прерванный прогон (готовые комбинации не повторяются) |
| `--only "lama-manga/*"` | запустить только подходящие комбинации (можно несколько раз) |
| `--max-images 1` | взять только первое изображение (быстрая проверка) |
| `--repeats N`, `--warmup N` | переопределить число измерений / прогревов |
| `--timeout-scale 2` | увеличить все таймауты |
| `--retry-failed` | вместе с `--resume`: повторить и неуспешные комбинации (прошлая попытка сохраняется) |

Ctrl+C — аккуратная остановка: текущий тест прерывается, результаты и отчёт сохраняются.
Второй Ctrl+C — немедленный выход.

**Пропустить только текущий тест** (например, слишком долгий на CPU): создайте пустой файл
`runs/<прогон>/STOP_CURRENT`. Тест будет остановлен и записан как «остановлено досрочно»,
прогон продолжится со следующей комбинации. Путь к файлу печатается перед каждым тестом.

Свои маски для lama-manga: `test_data/masks/<имя_страницы>.png` (белое = закрасить).
Без них маска = text + onomatopoeia из эталонного (CPU) прогона koharu-layout, расширенная на 4 px.

## Что и как тестируется

Подробное исследование, таблица комбинаций и причины исключений — [docs/research.md](docs/research.md).

| Модель | CPU | ROCm (gfx1031) | DirectML |
|---|---|---|---|
| koharu-layout-highres (rfdetr) | fp32 | fp32, fp16-autocast, fp32/fp16 + блочное внимание | fp32, fp32 + блочное внимание (rfdetr 1.5.2) |
| PaddleOCR-VL-1.6 | Paddle; torch bf16, fp32 | bf16, fp16 | bf16, fp16 (transformers 4.57 + custom code) |
| lama-manga (FFCResNetGenerator) | fp32 | fp32 | fp32 |

* **Веса — оригинальные**, из HF по зафиксированному commit hash. Никакого ONNX/GGUF/экспорта/конвертации.
  Приведение dtype (fp16/fp32) делается только в памяти и помечено в отчёте как отдельный вариант.
* Уровни поддержки в отчёте: **официально** (путь из документации + backend поддерживает устройство),
  **неофициально** (рабочая, но не задокументированная связка), **экспериментально**
  (даунгрейд библиотек против model card, nightly, обходные решения).
* Успехом считается только реальный инференс на тестовом изображении: установка пакета и
  smoke-test устройства — отдельные этапы, их статус виден в разделе «Окружения».

### Обходные решения, найденные при проверке на RX 6750 XT
* **Блочное внимание (`*-qchunk`)** для koharu-layout: в PyTorch+ROCm для gfx1031 нет flash/mem-efficient
  ядер SDPA, а MATH-ядро строит полную матрицу внимания (~14.6 ГиБ при 1920 px) → OOM на 12 ГБ.
  Внимание считается блоками по 2048 запросов — математически то же самое, веса не меняются.
* **KV-кэш для PaddleOCR-VL**: `generation_config.json` модели задаёт `use_cache=false`; без кэша
  страница не обрабатывалась и за 10 минут, с `use_cache=True` — 17–40 с на GPU. Включено во всех вариантах.
* **DirectML**: `torch.no_grad` вместо `torch.inference_mode` (иначе ошибка torch-directml);
  FFT (LaMa) и bf16 DirectML не поддерживает — процесс аварийно завершается, это фиксируется в отчёте.

## Изоляция и безопасность

* Глобальный Python не меняется. Оркестратор живёт в `.tools/venv`, интерпретаторы для
  окружений uv скачивает в `.tools/python`, окружения — в `.envs/<имя>`.
* Модели — в собственном кэше `models/` (пользовательский `~/.cache/huggingface` не используется).
* Кэши MIOpen (ROCm) — в `.cache/miopen`. Переменные окружения задаются только дочерним
  процессам; системные переменные и настройки драйвера не меняются. Права администратора не нужны.
* ComfyUI и другие окружения не используются и не затрагиваются.
* Каждый прогон — новый каталог `runs/<дата_время>`; повторное выполнение комбинации при
  `--resume` переносит прошлую попытку в `<вариант>_attempt<N>`, а не затирает её.
* Перед созданием окружения и скачиванием моделей проверяется свободное место.
* Тяжёлые инференсы на GPU идут строго последовательно; каждый — в отдельном процессе с
  общим таймаутом и таймаутом «нет прогресса», зависший процесс убивается вместе с потомками.

## Метрики

* **Время**: подготовка окружения, импорт+инициализация устройства, загрузка модели, первый
  инференс, прогрев, каждое измерение; mean / median / min / max / stdev, P95 при n ≥ 20.
  В инференс не входит чтение изображения и подготовка входа; входит перенос на устройство и
  копирование результата на CPU (для DirectML это единственный способ дождаться окончания вычислений).
* **Память**: RSS и private bytes дерева процессов воркера (psutil), доступная RAM до/после.
* **VRAM** — из трёх источников:
  1. счётчик Windows «GPU Process Memory» (Dedicated/Shared) по PID процесса — основной,
     видит выделения любого runtime (HIP, DirectML);
  2. аллокатор PyTorch (`max_memory_reserved/allocated`, только ROCm);
  3. «GPU Adapter Memory» — общая занятость адаптера и её прирост от фона (включает чужие процессы).
* **GPU**: загрузка движков процесса (PDH «GPU Engine»), сенсоры AMD через ADL драйвера —
  температура edge/hotspot, частота GFX/MEM, мощность ASIC. **CPU**: загрузка процесса, частота.
* Если метрика недоступна, в отчёте стоит «н/д», выдуманных значений нет.

## Результаты

```
runs/<дата_время>/
  summary.html / summary.json / summary.csv
  state.json                    — состояние для --resume
  logs/                         — orchestrator.log, install_*.log, smoke_*.log, freeze_*.txt
  masks/                        — маски, переданные в lama-manga
  <модель>/<backend>-<вариант>/
      job.json                  — точные параметры запуска
      result.json               — тайминги, версии, устройство, ошибки
      combo_summary.json        — то же + сводка ресурсов
      metrics.csv               — временной ряд ресурсов (4 Гц)
      worker.log, progress.jsonl
      outputs/<страница>/...    — выходы модели без изменений
```

## Структура кода

| Файл | Назначение |
|---|---|
| `run_all.py` | точка входа, бутстрап служебного окружения |
| `bench/orchestrator.py` | координатор |
| `bench/catalog.py` | модели, окружения, комбинации, исключения |
| `bench/envs.py` | создание окружений через uv |
| `bench/models.py` | скачивание моделей по revision |
| `bench/hardware.py`, `bench/winperf.py` | обнаружение железа; PDH / DXGI / ADL через ctypes |
| `bench/metrics.py` | сэмплер ресурсов |
| `bench/runner.py` | запуск воркера, таймауты, убийство дерева процессов |
| `bench/storage.py` | каталоги прогонов, state.json, resume |
| `bench/report.py` | отчёты |
| `bench/worker/` | код, исполняемый внутри окружений: `worker.py`, `backends.py`, `smoke.py`, `adapters/*` |

Новая модель = `ModelSpec` + `Combo` в `catalog.py` и адаптер в `bench/worker/adapters/`.
