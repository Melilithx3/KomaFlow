# komaflow — контекст для Claude Code

**komaflow** — личный сервис для команды перевода манги из трёх человек (клинер → переводчик → тайпер).
Клинер размечает страницы в десктоп-приложении и публикует их на сервер; переводчик переводит в вебе (в том числе с телефона);
по готовности любой участник скачивает PSD (клин, слой пометок, скрытый raw) для тайпинга в Photoshop; текст перевода тайпер копирует из веба.

Спецификация лежит в `docs/` и является источником истины. Читай её, а не угадывай. Этот файл — карта и правила работы.

## Нерушимые решения (не пересматривать без согласования с человеком)

1. Монорепо на TypeScript (pnpm workspaces). Сервер: Node + Fastify + SQLite (WAL). Веб: React + Vite. Десктоп: Tauri 2 + TS. Сайдкар: Python 3.12 + PyTorch ROCm.
2. Модели запускаются в формате safetensors на PyTorch. **Без ONNX, без DirectML.** Бэкенды сайдкара: ROCm (основной), CPU (запасной).
3. Идентификаторы страниц и объектов — UUID v7, их генерирует десктоп. Порядок чтения = позиция в массиве, а не отдельное поле, которое присылает клиент.
4. Данные делятся по владельцам: **геометрия, порядок, тип, клин — десктоп; перевод, состояние, комментарии, флажки — веб.** Оригинальный текст общий: десктоп обновляет его, только если веб не менял его с последней синхронизации, иначе — конфликт с явным выбором (ADR 0013). Правки одного не перезаписывают другое молча.
5. Версии независимы: `markup_rev` страницы (данные десктопа) и `text_ver` объекта (данные веба, с версиями по полям).
6. Ролей пользователей нет, все равны. Единственное ограничение — тип клиента: загрузка файлов и sync только с клиента `desktop`.
7. Статусы страниц **вычисляются**. Единственный ручной статус — `typed` («затайплена»).
8. raw и clean одной страницы всегда одного размера; сервер отвергает несовпадение. Разворотов нет.
9. Файлы адресуются по SHA-256 (content-addressed), отдаются с `Cache-Control: immutable`.
10. PSD, слои сверху вниз: `Notes`, `Raw` (скрыт по умолчанию), `Text` (группа, **после MVP**), `Clean`. **В MVP текстовых слоёв нет:** галочка «Текст» в диалоге экспорта выключена и неактивна (включить её нельзя), API отклоняет `layers.text = true` (422). Слои raw, clean, notes выбираются галочками. Текст тайпер берёт из веба (кнопки «Копировать»).
11. Сервер обязан работать на Orange Pi Zero 3 (Linux ARM64, 4 ГБ ОЗУ, SD-карта) и на Windows x64.
12. Интерфейс — только на русском. Код, комментарии, имена коммитов, README — на английском.

## Как работать

- Работай вертикальными срезами. После каждого среза: тесты зелёные, коммит (conventional commits), обновлён `docs/STATUS.md`.
- Неоднозначности решай сам и фиксируй в `docs/decisions/NNNN-title.md` (ADR, до 15 строк: контекст, решение, последствия). Человеку задавай вопрос только если решение необратимо дорогое или противоречит нерушимым пунктам выше.
- Всё, что нельзя проверить без железа (Photoshop, Orange Pi, GPU AMD, телефон), — пиши харнес и пошаговую инструкцию, добавляй в `docs/STATUS.md` раздел «Нужно от человека» и продолжай с тем, что от этого не зависит.
- Зависимости добавляй осознанно. Нативные модули проверяй на ARM64 (см. спайк S3).
- Секреты и данные не коммитить (`.env`, `data/`, `.envs/`, `models/`, `*.psd`, тестовые страницы).

## Соглашения

- TypeScript `strict`, без `any`. **zod — единственный источник схем**: типы, валидация, OpenAPI выводятся из `packages/contract`.
- Формат ошибок API единый (см. `docs/02-api.md`). Время — ISO 8601 UTC. Координаты — целые пиксели raw-страницы, начало в левом верхнем углу.
- Миграции БД — нумерованные SQL-файлы, без ORM-магии.
- Тесты: vitest; для сервера — интеграционные на реальном SQLite во временной папке.
- Чистые функции без зависимостей (канонический JSON, `psd_input_hash`, порядок чтения, геометрия) живут в `packages/contract` и используются всеми частями.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm install` | зависимости (Node ≥ 24.7, pnpm 10) |
| `pnpm test` / `pnpm lint` / `pnpm typecheck` | все проверки (vitest projects) |
| `pnpm build` | сервер (`apps/server/dist`) и веб (`apps/web/dist`) |
| `pnpm dev:server` | API на :8787, читает `apps/server/.env` (пример: `.env.example`, `KOMAFLOW_DEV=1`) |
| `pnpm dev:web` | Vite на :5173, проксирует `/api` на :8787 |
| `pnpm --filter @komaflow/server admin -- <cmd>` | `komaflow-admin` из исходников (в проде: `node apps/server/dist/admin.js`) |
| `KOMAFLOW_DEV=1 pnpm --filter @komaflow/server admin -- seed --fixtures` | демо-пользователь `demo` / `demo-password` + фикстурная глава |
| `pnpm seed -- --url http://127.0.0.1:8787 --login demo --password demo-password` | сид через HTTP API (как десктоп) |
| `pnpm --filter @komaflow/tools s1` | харнес спайка S1 (PSD в `tools/spikes/s1-psd/out/`) |
| `bash tools/spikes/s3-arm/run.sh` | харнес спайка S3 (на Orange Pi) |
| `node apps/server/dist/server.js` | прод-сервер (после `pnpm build`), отдаёт и API, и веб |
| `pnpm --filter @komaflow/desktop dev` | UI десктопа в браузере (:1420, прокси на :8787) |
| `pnpm --filter @komaflow/desktop tauri dev` / `tauri build` | десктоп в Tauri / установщик (нужен Rust) |
| `cd sidecar && .venv/Scripts/python -m pytest` | тесты сайдкара (заглушки моделей) |
| `komaflow-sidecar install` / `analyze --pages … --out … --overlay` / `serve --token …` | движок анализа |
